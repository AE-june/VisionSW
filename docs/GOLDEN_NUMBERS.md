# GOLDEN_NUMBERS.md — V3/V4 검증 기준값

ARCH 변경 전/후 회귀를 검출하는 수치 기준.  
값을 갱신할 때는 반드시 커밋 해시와 날짜를 기록한다.

---

## V3 반복성 기준선 (ARCH 변경 전 측정)

**목적:** ARCH Phase 1~6 작업 후 σ가 기준 대비 ×1.10 이내인지 확인.  
**측정 명령:**
```powershell
.\build\bin\Release\VisionEngine.exe --repeat-analyze <recipe.json> <png_folder> out.csv
```
출력 CSV: `파일명, zMm_0, zMm_1, ..., planeA, planeB, planeC, rmse, tilt`  
각 컬럼 σ를 `stdDev()` 로 계산해 아래 표에 기록.

| 레시피 | 측정 항목 | 기준 σ (mm) | 커밋 | 날짜 |
|--------|-----------|------------|------|------|
| *(미측정 — 실데이터 폴더 경로 지정 후 실행)* | | | | |

**채우는 법:** 실데이터 N≥10장으로 실행 → CSV에서 각 컬럼 σ 계산 → 위 표에 기입.  
ARCH 변경 후 σ ≤ 기준 × 1.10 이면 통과.

---

## V4 골든 넘버 (대표 레시피 고정값)

**목적:** 특정 입력에 대해 출력값이 변하지 않았는지 확인 (설계 변경 의도 없는 회귀 검출).  
아래 레시피·데이터 조합으로 측정한 값을 고정. 변경 시 이유를 명시.

| 레시피 | 입력 파일 | 측정 항목 | 기댓값 | 허용 오차 | 커밋 | 날짜 |
|--------|-----------|-----------|--------|-----------|------|------|
| *(미기록 — 대표 레시피 확정 후 기입)* | | | | | | |

**채우는 법:**
1. 대표 레시피 1~3개 선정 (자주 쓰는 RegionMeasure·PlaneFit 포함)
2. 고정 입력 파일 1장으로 `--repeat-analyze` 또는 UI에서 실행
3. 측정값 기록, 허용 오차는 `zResMm/2` 또는 `σ×3` 중 큰 값 사용

---

## 갱신 규칙

- ARCH 변경 전: V3 기준 σ 측정·기록 필수
- ARCH 변경 후: V3 재측정, 기준 × 1.10 초과 시 코드 검토
- 의도적 수치 변경(버그 수정·알고리즘 개선): 이유 한 줄 + 새 값으로 갱신
- 갱신 시 커밋 해시 필수 기록
