### 1.4 HeightMap 인코딩 규약 — T0-4의 핵심 함정

```cpp
// Core/include/HeightMap.h
std::vector<float> data;   // planar raw. NaN = 무효
float zResMm, zZeroCount;
float zMm(int col,int row) const { return (rawAt(col,row) - zZeroCount) * zResMm; }
float xMm(int col) const { return (col - originCol) * xResMm; }
```

`data`는 **mm가 아니라 raw count**다. 값을 바꾸는 노드(T0-4 레벨링, T0-5 Subtract)는 mm로 계산한 결과를 **raw로 되돌려 저장**해야 한다:

```
raw_new = z_new_mm / zResMm + zZeroCount
```

여기서 정밀도 문제가 생긴다. §3.1 D-1에서 결정한다.

## 3. T0-4 레벨링

### 3.0 왜 필요한가

[벤치마크 §2-B1](./3D_BASELINE_BENCHMARK.md) — 조사한 5개 제품 중 4개가 보유. 미보유는 HALCON뿐이고 HALCON은 높이맵 전용 타입이 없어서다.

| 제품 | 대응 |
|---|---|
| Aurora | `FlattenSurface`, `FlattenSurface_WithScalePreserving`, `SurfaceToPlaneDistanceImage` |
| eVision | ZMap Leveling |
| Gocator | Tilt Correction (Hole/Stud/Opening 툴마다. 문서가 *"Surface Plane 툴의 X/Y Angle 출력을 복사해 넣으라"*고 명시) |
| InsWorks | `DiffReferBasePlane` |

**효과**: 출력이 "평면 대비 부호 있는 거리맵"이 되므로 이후 모든 임계값·결함검출이 절대 Z가 아니라 **상대 높이**로 동작한다. 파트가 매번 조금씩 기울어 놓이는 실제 환경에서 임계값을 스캔마다 다시 잡지 않아도 된다.

**현재 VisionSW**: `PlaneFit`이 `PlaneModel`을 내지만 **그걸로 맵을 펴는 노드가 없다.** `HeightMeasure`가 내부에서 평면까지 수직거리를 계산하지만 그건 ROI 측정값이고, 맵 전체를 상대 높이로 바꾸는 수단이 아니다.

### 3.1 노드 설계 — `Level` 하나로 통합

Aurora는 `FlattenSurface`와 `SurfaceToPlaneDistanceImage`를 분리했지만 계산이 거의 같다. **출력 모드 파라미터를 가진 단일 노드**로 만든다.

```
Level
  입력  : HeightMap, Plane
  출력  : HeightMap
  카테고리: 변환
```

**파라미터**

| 이름 | 타입 | 기본 | 의미 |
|---|---|---|---|
| `mode` | `"distance"` \| `"flatten"` | `"distance"` | 출력 의미 (아래) |
| `keepInvalid` | bool | `true` | 입력 NaN을 출력 NaN으로 보존 |
| `offsetMm` | double | `0.0` | 결과에 더할 상수 (음수 회피용) |

**`mode` 정의 — 부호 규약을 코드와 문서에서 일치시킬 것**

```
distance : out(c,r) = signedDistance(x,y,z)            [평면까지 수직거리]
           = (z − (a·x + b·y + c)) / sqrt(1 + a² + b²)
           PlaneModel::signedDistance()를 그대로 쓴다. 평면 위(+z)면 양수.

flatten  : out(c,r) = z − (a·x + b·y + c)              [수직 정규화 없이 Z만 뺌]
           기울기가 작을 때 distance와 거의 같지만 값이 다르다.
           Aurora의 FlattenSurface_WithScalePreserving 계열에 해당.
```

두 모드를 반드시 구분해 구현하고, 어느 쪽을 기본으로 할지는 **`distance`**로 한다 — `HeightMeasure`가 이미 `signedDistance()`를 쓰므로 측정값 의미가 일관된다.

### D-1 결정 필요 — 출력 Z 인코딩

`data`는 raw count다(§1.4). 레벨링 결과는 0 근처의 작은 값이 되므로 인코딩 선택이 정밀도를 좌우한다.

| 안 | 출력 `zResMm` | 출력 `zZeroCount` | 평가 |
|---|---|---|---|
| **A. 입력 유지** | 입력과 동일 | 입력과 동일 | 다운스트림이 아무 변경 없이 동작. 단 `raw = z/zResMm + zZeroCount`로 되돌릴 때 큰 `zZeroCount`(16bit 센서 32768) 근처에서 float 유효자릿수를 소모 |
| **B. 0 기준 재인코딩** | 입력과 동일 | `0` | `raw = z/zResMm`. 0 근처 값이라 float 정밀도가 최대. 다운스트림 `zMm()`도 그대로 동작 |
| C. mm 직접 저장 | `1.0` | `0` | 가장 단순하나 분해능 정보가 소실되어 다른 노드와 규약이 깨짐 |

**권장: B.** 근거 — `zResMm=0.001`, 레벨링 결과 ±0.5mm 범위면 raw는 ±500. float 유효자릿수 24bit로 충분하다. A는 32768 + 500 형태가 되어 상대 정밀도가 약 65배 나빠진다.

**단 구현 전에 실측으로 확인할 것**: 대표 레시피의 `zZeroCount`·`zResMm` 실값을 로그로 찍고, A안에서 실제로 유효자릿수 손실이 측정값에 나타나는지 확인한다. 나타나지 않으면 A가 더 안전하다(다운스트림 가정 변화 0). **확인 결과를 §9에 追記한다.**

### 3.2 프레임 규약

```
입력 HeightMap.frameId = HF
입력 PlaneModel.frameId = PF

HF == PF 또는 둘 중 하나가 ""   →  그대로 계산
HF != PF (둘 다 비어있지 않음)  →  FrameRegistry::transform(PF, HF)로 평면을 HF로 변환한 뒤 계산
변환 실패                        →  ToolStatus::Fail + 메시지 (조용히 계산하지 말 것)
```

**출력 `frameId` = 입력 HeightMap의 `frameId`.** 격자가 바뀌지 않으므로 새 프레임이 아니다. `definedFrames`는 비운다.

**평면 프레임 변환은 T0-1 Phase 3 범위와 겹친다.** 선행 문서 §3.6 Phase 3의 3-3 항목(평면 프레임 변환 + 왕복 테스트)이 아직 미착수다. 처리 방침:

- 이 문서에서는 **`HF != PF`인 경우 일단 `Fail`로 처리**한다. 변환 구현은 T0-1 Phase 3에 맡긴다.
- 현재 `Align`이 프레임을 만들지 않으므로(§1.2) 실전에서 `HF != PF`가 발생하지 않는다. Fail 처리로 충분하고, 발생하면 그 자체가 알림이 된다.
- T0-1 Phase 3 완료 후 이 분기를 변환으로 승격한다. **TODO 주석에 `T0-1 P3` 태그를 남길 것.**

### 3.3 NaN·경계 규약

- 입력 NaN → 출력 NaN (`keepInvalid=true`). `false`면 평면값 기준 0으로 채운다.
- 평면이 `valid=false`면 `ToolStatus::Fail`. 입력을 그대로 통과시키지 말 것 — 조용한 오류가 된다.
- 채널: **채널0(height)만 변환한다.** 다른 채널(intensity 등)은 그대로 복사. `channelRoles`를 보존한다.

### 3.4 성능

34M px 전체를 훑는다. [perf_findings.md](../perf_findings.md)의 교훈을 그대로 적용한다:

> 메모리 대역폭 바운드 선형 패스는 `cv::parallel_for_`로 병렬화하면 **오히려 느려진다.** NoiseFilter glue 루프가 462→666ms로 악화된 실측 사례.

레벨링은 픽셀당 몇 번의 곱셈·덧셈뿐인 **선형 패스**다. 따라서:

- **먼저 직렬로 구현하고 실측한다.** 병렬화를 기본으로 넣지 말 것.
- `a·x + b·y`는 행마다 `b·y`가 상수 → **행 루프 밖에서 계산**하고 열 방향은 `a·xResMm` 증분 누적으로 처리한다. 곱셈을 줄이는 이 최적화가 병렬화보다 확실하다.
- `1/sqrt(1+a²+b²)`는 **루프 밖에서 1회** 계산해 상수로 쓴다.
- 프레임 변환이 필요해질 경우에도 **루프 안에서 `transform()`을 호출하지 말 것.** 밖에서 1회 계산해 계수에 접어넣는다.

### 3.5 수용 기준

- 합성 데이터 단위 테스트:
  - 정확히 평면인 입력 → `distance` 출력이 전부 0 (허용오차 이내)
  - 기울어진 평면 + 알려진 단차 → 단차값이 정확히 복원
  - `distance` vs `flatten`이 기울기 0에서 일치, 기울기가 크면 `sqrt` 인자만큼 차이
  - NaN 보존
  - 다채널 입력에서 채널0만 변경, 나머지 bit-identical
  - `plane.valid == false` → Fail
  - `HF != PF` → Fail
- `HeightMeasure`와의 정합: `Level(distance)` 출력에 대해 ROI 평균을 직접 계산한 값이 `PlaneFit → HeightMeasure(Mean)` 결과와 일치. **이게 가장 중요한 검증이다** — 두 경로가 같은 부호·같은 수직거리 정의를 쓰는지 증명한다.
- §6 회귀검증 CSV diff 0 (신규 노드이므로 당연히 0이어야 함).

## 4. T0-5 표면 기본변환

노드 4개. 난이도·위험도 순으로 정렬했다.

### 4.1 `ValidRegion` — 유효 픽셀 → Region

```
입력  : HeightMap
출력  : Region
카테고리: 분할
```

[벤치마크 §2-A3](./3D_BASELINE_BENCHMARK.md). Aurora `SurfaceValidPointsRegion` / `Point3DGridValidPointsRegion`, Gocator `Preserve Invalid`.

**용도**: 평균·σ 같은 통계를 무효 픽셀 오염 없이 내기 위한 전제. `GapFill`로 채운 픽셀과 실측 픽셀을 구분하는 수단이기도 하다 — [repeatability_findings.md](../repeatability_findings.md)의 "고노출 fill 스파이크가 측정을 ±0.1mm 요동" 사례가 정확히 이 구분이 없어서 생긴 문제다.

**파라미터**

| 이름 | 기본 | 의미 |
|---|---|---|
| `channel` | `0` | 어느 채널의 유효성을 볼지 |
| `invert` | `false` | true면 무효 픽셀 집합을 낸다 |

**규약**: 출력 `Region::frameId` = 입력 `HeightMap::frameId`. `width/height` = 입력과 동일. 가장 단순한 노드이므로 **여기서 프레임 전파 패턴을 확립**하고 나머지가 따른다.

### 4.2 `SurfaceSubtract` — 두 표면 차분

```
입력  : HeightMap (A), HeightMap (B)      ← 같은 타입 입력 2개
출력  : HeightMap
카테고리: 변환
```

[벤치마크 §2-B3](./3D_BASELINE_BENCHMARK.md). Aurora `SubtractSurfaces`. **골든 비교(F4)의 최소 구현**이기도 하다 — 기준 스캔과 빼서 편차맵을 낸다.

**이 노드가 T0-2 B-1의 첫 실전 수혜자다.** 같은 타입 입력 2개는 `Edge`에 포트 핸들이 없던 시절에는 구분이 불가능했다(선행 문서 제약 C-1). 이제 `targetPort`로 A/B를 구분할 수 있다.

**구현 시 반드시 확인할 것**: `main.cpp`의 입력 병합이 **포트 인덱스 기준으로 A와 B를 올바르게 나누는지**. 선행 문서 §4.6 Phase 2가 이 전환을 다뤘으나 실제 배선 상태를 코드로 확인해야 한다. 슬롯 기반 "먼저 온 것이 이김"이 남아 있으면 A/B가 섞인다.

**파라미터**

| 이름 | 기본 | 의미 |
|---|---|---|
| `absolute` | `false` | true면 \|A−B\| |
| `nanPolicy` | `"propagate"` | `propagate`(어느 한쪽 NaN → NaN) \| `zero`(NaN을 0으로) |

**규약**
- 두 입력의 `width/height`가 다르면 `Fail`. 리샘플을 사용자가 명시적으로 넣게 한다 (조용한 보간 금지).
- 두 입력의 `frameId`가 다르면 `Fail` (§3.2와 동일 방침, `T0-1 P3` TODO).
- 두 입력의 `xResMm/yResMm/zResMm`이 다르면 `Fail`.
- 출력 `frameId` = A의 `frameId`. Z 인코딩은 D-1 결정을 따른다.

### 4.3 `SurfaceCrop` — 크롭

```
입력  : HeightMap, Region (선택)
출력  : HeightMap
카테고리: 변환
```

[벤치마크 §2-B2](./3D_BASELINE_BENCHMARK.md). Aurora가 5종(`CropSurface`, `CropSurfaceToBox3D`, `CropSurfaceToRegion`, `CropSurfaceByPlaneProximity`, `CropSurfaceByNeighborsProximity`), eVision이 4종(`ESimpleCropper`, `ERectangularCropper`, `ESphericalCropper`, `EPlaneCropper`). **좌표 기반뿐 아니라 기하 조건 크롭이 공통**이라는 게 핵심이다.

**Phase 3에서는 좌표·Region 크롭만 구현한다.** 평면근접·이웃근접은 Phase 4 이후 또는 후속 문서로.

**파라미터**

| 이름 | 기본 | 의미 |
|---|---|---|
| `mode` | `"rect"` | `rect`(픽셀 사각) \| `region`(Region 바운딩박스로 잘라내고 밖은 NaN) |
| `rect` | `{x:0,y:0,w:0,h:0}` | `mode=rect`일 때. `w/h=0`이면 전체 |
| `outsideNaN` | `true` | `mode=region`에서 Region 밖 픽셀을 NaN으로 |

### ⚠️ `SurfaceCrop`은 **새 프레임을 정의해야 한다**

크롭은 `width/height`와 **원점의 픽셀 기준이 바뀐다.** 여기가 T0-1 규약의 첫 실전 적용 지점이다.

```
입력 프레임 HF, 크롭 오프셋 (dx, dy) px

출력 HeightMap:
  width  = w,  height = h
  originCol = 입력 originCol − dx      ← 같은 물리점이 같은 mm를 갖도록
  originRow = 입력 originRow − dy
  xResMm/yResMm/zResMm/zZeroCount = 입력과 동일
  frameId = "hm:<nodeId>"              ← 신규 프레임

출력 definedFrames:
  Frame{ id="hm:<nodeId>", parentId=HF, toParent=identity }
```

**`toParent`가 identity인 이유**: `originCol`을 함께 조정하므로 `xMm()`이 이미 같은 mm를 반환한다. 즉 mm 좌표계는 안 바뀌고 픽셀 인덱싱만 바뀐다. **프레임을 새로 만드는 것은 mm가 달라서가 아니라 격자가 달라졌음을 표시하기 위해서다** — 이렇게 해두면 이 출력에서 만든 Region을 원본 HeightMap에 적용하려는 시도가 `frameId` 불일치로 잡힌다(선행 문서 결함 2).

**대안 검토 (D-2)**: `originCol`을 조정하지 않고 `toParent`에 `tx = -dx·xResMm`를 넣는 방법도 있다. 이쪽이 개념적으로 더 깨끗하지만, 프레임 변환을 실제로 적용하는 소비자가 아직 없어서(T0-1 Phase 2가 부분 완료) 지금 도입하면 mm 좌표가 조용히 틀어진다. **`originCol` 조정 방식으로 간다.** T0-1 Phase 4에서 재검토.

### 4.4 `SurfaceResample` — 리샘플

```
입력  : HeightMap
출력  : HeightMap
카테고리: 변환
```

[벤치마크 §2-A4](./3D_BASELINE_BENCHMARK.md). Aurora `ResampleSurface`/`ReduceSurface`, eVision `EGridDecimator`, Gocator Decimation.

**주의**: 측정 경로에서 분해능 하락은 곧 정밀도 하락이다. 프리뷰·초기 정렬용이라는 걸 노드 설명(tooltip)에 명시한다.

**파라미터**

| 이름 | 기본 | 의미 |
|---|---|---|
| `mode` | `"factor"` | `factor`(정수 배율) \| `resolution`(목표 mm/px) |
| `factor` | `2` | `mode=factor`. 2 = 가로세로 1/2 |
| `targetXResMm` / `targetYResMm` | `0` | `mode=resolution` |
| `method` | `"decimate"` | `decimate`(격자 샘플링, 무효 전파 없음) \| `meanValid`(유효 픽셀 평균) |

**`method` 선택이 중요하다.** `decimate`는 원본 값을 그대로 쓰므로 측정값이 보존되지만 노이즈에 취약하다. `meanValid`는 평활 효과가 있지만 **원본에 없던 값을 만든다** — 측정 경로에 쓰면 안 된다. 기본을 `decimate`로 두고 `meanValid`는 명시 선택으로 한다.

**프레임**: `SurfaceCrop`과 같은 방식으로 **새 프레임을 정의**한다. 단 여기서는 `xResMm`이 실제로 바뀐다:

```
출력 xResMm = 입력 xResMm × factor
     originCol = 입력 originCol / factor      ← mm 좌표 보존
     frameId = "hm:<nodeId>", parent = 입력 frameId, toParent = identity
```

**`ExposureMerge2/3`의 `halfRes: true`가 같은 문제를 이미 갖고 있을 가능성이 높다.** 선행 문서 §9 미결정 2번 항목이다. **`SurfaceResample` 구현 시 `ExposureMerge2/3`의 `halfRes` 경로가 `xResMm`·`originCol`을 어떻게 처리하는지 반드시 확인하고, 불일치하면 보고할 것.** 같은 규약을 써야 한다.


각 Phase 후 §6 회귀검증.

### 5.3 왜 이 순서인가

- **ValidRegion 먼저**: 값을 안 바꾸므로 프레임 전파 규약만 검증된다. 여기서 패턴이 틀리면 나머지 4개가 다 틀린다.
- **Level이 두 번째**: D-1(Z 인코딩)은 이후 모든 값-변경 노드가 따라야 하는 결정이다. 여기서 못박는다.
- **Subtract가 세 번째**: 포트 라우팅이 실제로 동작하는지 확인하는 첫 노드다. 여기서 A/B가 섞이면 T0-2 B-2가 미완이라는 뜻이므로 즉시 발견된다.
- **Crop/Resample이 마지막**: 새 프레임 정의는 되돌리기 가장 어렵다. 앞 3개로 규약이 검증된 뒤에 한다.

## 7. 금지 사항

9. **자동 커밋 금지.** 각 Phase 완료 후 diff를 보고하고 승인받는다.

## 7.5 완료 보고 규칙 (**필수**)

Phase 완료 보고에 **"확인했습니다"류 요약을 쓰지 않는다.** 아래를 그대로 붙인다.

### 보고에 반드시 포함할 것

1. **실행한 명령 원문** — 축약·의역 없이 그대로.
2. **그 명령의 출력 원문** — 특히 `diff baseline.csv after.csv`의 출력. **아무것도 안 나왔으면 "출력 없음(diff 0)"이라고 명시**한다. 실행 안 하고 넘어간 것과 구분되어야 한다.
3. **`ctest` 요약 줄** — `100% tests passed, 0 tests failed out of N` 형태의 실제 줄.
4. **변경 파일 목록 + diff** — 문서에 명시되지 않은 파일을 건드렸으면 **그 이유를 별도로 밝힌다.**
5. **문서에 없는 결정을 내렸으면 그 목록.** §9 미결정 항목을 확정했으면 문서에 追記한 내용도 함께.
6. **체크리스트 항목별 상태** — 완료/미완/해당없음. **부분 완료를 완료로 보고하지 않는다.**

### 왜 이 규칙이 있는가

이 프로젝트에서 실제로 발생한 일이다. 선행 문서(T0-1/T0-2)가 "전부 구현 완료"로 보고됐으나 독립 감사에서 다음이 미완으로 확인됐다:

- T0-1 Phase 2 부분 — `frameId`를 다루는 VisionTools가 `NoiseFilter.cpp` 하나뿐
- T0-1 Phase 3 — `AlignTool.cpp`가 여전히 `originCol/originRow` 직접 대입, 회전 없음
- T0-1 Phase 3-2 — `RefPoint`/`OriginCoord`의 px/mm 이중 보유 그대로
- T0-2 B-4 — 브로드캐스트 실행 루프 미배선 (스캐폴딩만)

또한 툴 4개(`ImageLoader`·`EdgeDetector`·`RefHeight`·`ThicknessMeasure`)가 삭제됐으나 **보고에 포함되지 않았다.**

**요약 보고는 신뢰할 수 없다. 명령과 출력 원문만 신뢰한다.**

### 검증 담당 분리

| 검증 항목 | 담당 |
|---|---|
| 빌드 · `ctest` · `--repeat-analyze` CSV diff · 성능 실측 | Claude Code (실행 가능한 유일한 주체) |
| 코드 리뷰 (스펙 준수·규약 위반) | **Claude Code의 subagent** — 구현 컨텍스트를 못 보는 새 세션이어야 자기확인 편향이 줄어든다 |
| 체크리스트 항목별 실재 확인 · 문서↔코드 어긋남 | 별도 감사 세션 (구현하지 않은 주체) |

**같은 컨텍스트에서 자기 코드를 리뷰하지 말 것.** 고위험 Phase(2·4·5)는 반드시 subagent 검증을 거친다.
